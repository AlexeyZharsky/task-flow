# TaskFlow

Приложение для управления задачами с Kanban-досками, разработанное в рамках тестового задания.

**Рабочая версия:** https://task-flow-theta-pied.vercel.app/

## Возможности

### Аутентификация

* Регистрация по email и паролю
* Вход и выход из аккаунта
* Защищенные маршруты
* Аутентификация реализована с помощью Supabase Auth

### Kanban-доски

* Просмотр досок пользователя
* Создание доски
* Удаление доски
* Открытие доски
* Автоматическое создание трех стандартных колонок

### Колонки

* Создание колонок
* Переименование колонок
* Удаление колонок

### Задачи

* Создание задач
* Удаление задач
* Перемещение задач между колонками с помощью drag-and-drop
* Изменение порядка задач внутри колонки
* Порядок задач сохраняется в базе данных

## Архитектура

Проект организован по зонам ответственности:

```text
src/
├── components/
│   ├── auth/
│   ├── board/
│   ├── task/
│   └── shared/
├── hooks/
├── pages/
├── providers/
├── services/
├── types/
└── utils/
```

* `components` — переиспользуемые UI-компоненты
* `hooks` — специфичные для приложения React-хуки
* `pages` — компоненты, соответствующие маршрутам приложения
* `services` — работа с Supabase API и операции с базой данных
* `providers` — контексты и провайдеры приложения
* `types` — TypeScript-типы
* `utils` — переиспользуемая бизнес-логика и вспомогательные функции

## База данных

Приложение использует PostgreSQL через Supabase.

Основные сущности:

```text
boards
board_members
columns
tasks
profiles
```

Row Level Security (RLS) включен для ограничения доступа к доскам пользователя и связанным с ними данным.

## Запуск проекта

### Требования

* Node.js
* npm
* Проект Supabase

### Установка

Клонируйте репозиторий:

```bash
git clone https://github.com/AlexeyZharsky/task-flow.git
```

Перейдите в директорию проекта:

```bash
cd task-flow
```

Установите зависимости:

```bash
npm install
```

Проект использует Supabase для:

- PostgreSQL базы данных;
- аутентификации пользователей;
- Row Level Security (RLS);
- серверных PostgreSQL-функций для операций с данными.

Схема базы данных и настройки backend хранятся в репозитории в директории:

```text
supabase/
└── migrations/
    └── 20260823161207_initial_schema.sql
```

Создайте файл с переменными окружения:

```bash
cp .env.example .env
```

Добавьте данные Supabase в `.env`:

```env
VITE_SUPABASE_URL=your_supabase_project_url
VITE_SUPABASE_PUBLISHABLE_KEY=your_supabase_publishable_key
```

Запустите сервер разработки:

```bash
npm run dev
```

Приложение будет доступно по адресу:

```text
http://localhost:5173
```

Файл `.env.example` содержит только названия необходимых переменных без реальных ключей.
